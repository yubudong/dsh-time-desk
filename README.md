# 时间工作台 · Time Desk

DSH 原生个人时间工作台：在侧栏管理项目、待办、习惯、公历／农历重复安排、日历、番茄钟和复盘。内置「时间精灵 · Time Spirit」，通过自然语言操作同一份工作台数据。

**包名：`dsh-time-desk` · 版本：0.5.3 · MIT**

![时间精灵](assets/time-spirit-a.gif)

## 功能

- **项目与任务**：项目进度、子步骤、预计番茄数、当天重点、截止提醒；普通任务到达安排日后，未完成就持续出现在后续日期的当天待办，保留原日期。过往定时任务作为续办显示，不伪造成当天的新预约。没有安排日期的事项留在收集箱，明确改期到未来的任务尊重改期。
- **习惯**：打卡、数量累加、每周次数目标；按早晨／不限／晚上分组，支持安排今天、跳过剩余和记录未达成。
- **日历与重复**：每日、每周、每月、每年、自定义间隔、完成后间隔；支持农历年度事件、闰月策略和月份缺日处理。单次改期与整组规则分开。
- **专注计时**：关联任务或自由专注；单次／默认时长独立；暂停不累计有效专注。完整保存后计一个番茄，提前结束只记录时间，不自动完成任务。
- **四种表盘**：极简数字、经典圆盘、翻页时钟、沙漏；黑色全屏可切换普通时钟。退出全屏不改变计时，屏幕唤醒和系统全屏取决于客户端支持。
- **回顾与备份**：每日／每周笔记、专注记录、JSON 导出恢复、回收站；恢复前保存副本。
- **时间精灵**：独立 DSH Agent 对话、模型选择、操作回执；只开放工作台业务工具。图标为薄荷绿精灵轻动画，支持减少动态效果时显示静态图。

## 兼容与安装

需要 **DeepSeek Harness 0.2.2-rc.2 或更高的 0.2.x 版本**。兼容声明为 `>=0.2.2-rc.2 <0.3.0`；后续 DSH 主版本需重新核对 API。

插件无原生运行时依赖。分发包包含预构建 Host／Client 文件，不要求安装者运行 npm 或编译。

1. 下载发行的 source zip 并解压。
2. 在 DSH 插件管理器中安装包含本 README 与 `package.json` 的 `dsh-time-desk` 目录。
3. 按管理器返回的结果操作；如提示重启，请重启。
4. 从侧栏打开「时间工作台」。首次安装是空白工作台，自己添加任务和习惯。

仓库发布后也可使用固定 Git Commit 安装。安装地址应指向实际公开的完整 40 位 Commit，不能把尚未发布的版本当成可下载版本。

当前在 macOS DSH Desktop 上开发；Windows 实机、系统通知和不同客户端的原生全屏仍需实际交互验收。CI 定义了 macOS／Windows／Linux 与 Node 22／24 的构建检查，配置存在不代表已在远端运行。

## 从 dsh-life-desk 升级

0.5.0 将发布包更名为 `dsh-time-desk`，产品名保持「时间工作台」，AI 助手保持「时间精灵」。

- 在同一个 DSH Profile 中移除旧的 `dsh-life-desk` 包注册，再安装 `dsh-time-desk`。不要同时启用两个包。
- 主存储单元仍为 `life_desk_v1`，助手指针仍为 `life_desk_spirit`。移除包注册不等于删除独立存储；不要手动清空 Profile 或存储。
- 保留内部 `life-desk` 面板／入口 ID、`life_desk` 工具名与既有路由，保证现有调用和会话衔接。
- 新导出的备份格式名为 `dsh-time-desk`，仍接受旧 `dsh-life-desk` 备份。旧版本不一定能读取新格式，避免降级覆盖数据。

## 快速使用

1. 用快速记录收集待办，日期可以留空；需要安排时再选择日期和时间。
2. 新建项目并关联任务；编辑任务可填写预计番茄数，0 表示不估算。
3. 数量型习惯允许分次记录；每周次数目标按不同日期计算，只有主动安排后才进入当天执行区。
4. 点击任务旁的计时器，或在专注区选择任务；点击「专注时长／下一轮」设置仅本次时长或默认时长。
5. 一次性尚未开始的时长选择只存在当前客户端，刷新后恢复默认；开始后该轮时长持久保存。修改默认值不影响当前计时。
6. 点击「全屏专注」查看大表盘；普通时钟显示工作台时区当前时间，不产生专注记录。Esc 退出。
7. 在「回顾」保存日／周笔记，在「设置与备份」导出自己的 JSON。

计时按持久化时间戳恢复，长时间离开或电脑休眠后应核对有效专注秒数。每轮需主动开始和确认，不会离线自动累计多轮。显示亮度只调整表盘，不改变系统屏幕亮度。

## 用自然语言管理

可在 DSH 对话中使用 `life_desk`，或打开右上角「时间精灵」：

- “建一个阅读项目，先列三条不设日期的待办。”
- “设置每周三次的运动习惯，不固定星期。”
- “为这个任务开始一轮 15 分钟专注，只用于本轮。”
- “把表盘改成沙漏，不改变当前计时。”

工具首次调用 `help` 获取字段说明，修改前 `read` 获取 revision 与记录 ID。明确的新增或打卡可以直接执行；批量调整、整组重复事项修改和覆盖恢复需要先确认范围。

时间精灵使用你在 DSH 配置的模型和凭据，产生所选模型的正常用量。手动操作不需要模型请求。关闭助手侧栏不会回滚已完成的修改。

## 隐私与数据

**代码仓库和发行包不包含开发者的任务、习惯、账期、打卡、专注记录、备份、对话或模型密钥。**

工作台数据通过 DSH 存储后端写入当前 Profile，独立于插件安装目录。时间精灵聊天保存在独立 DSH Session 中；工作台 JSON 备份不包含该聊天历史。

本项目没有独立账号、云同步或遥测服务。调用时间精灵时，用户输入及工具读取的相关内容会进入所选模型的对话上下文；是否发送到远端由 DSH 的模型配置决定。

自己的 JSON 备份和工作台截图可能包含个人信息，不应提交到仓库或 Issue。详见 [PRIVACY.md](PRIVACY.md)。

## 开发

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run privacy
npm run check
npm run build
npm test
npm pack
```

核心源码：`src/model.js` 为业务和事务，`src/schema.js` 为验证，`src/dates.js` 为日期规则，`src/host.js` 注册服务和工具，`src/client.tsx` 为界面，`src/TimerUI.tsx` 为计时与全屏。

构建会把运行依赖与图片打包进 dist，React 使用 DSH 提供的版本。无安装生命周期脚本，不在安装时运行构建。源码提交前运行隐私检查；具体发布与市场投稿步骤见 [PUBLISHING.md](PUBLISHING.md)。

## 版本与更新

「设置与备份 → 版本与更新」显示当前版本、安装方式与上次检查时间，并可手动检查稳定版更新。自动检查默认关闭；开启后最多每天检查一次，只读取项目 GitHub 上的公开发布信息，不上传任务或聊天内容。

发现新版时可查看更新说明、打开 DSH 插件管理或忽略该版本。工作台**不下载、不安装、不覆盖插件文件**；升级始终由 DSH 插件管理器执行。本地开发目录安装会被明确标出，不会从这里自动更新。无法读取当前 DSH 版本时，界面会说明兼容性无法确认，而不是显示为可安全升级。

## 自动发版

维护者更新包版本、填写 `changes/版本号.md` 并提交预构建文件后，推送 `v版本号` 标签即可触发隐私与跨平台检查、归档校验和草稿到公开 Release 的流程。测试版标为 Pre-release，不替换稳定版；公开版本禁止自动覆盖。

市场同步独立运行：未配置跨仓库授权时生成可下载的投稿材料；配置专用授权后可更新已有目录 PR，DSH STORE 继续使用其扫描与审核流程。此功能不在用户设备上自动安装更新。操作与重试见 [PUBLISHING.md](PUBLISHING.md)。

## 限制

- 当前没有云同步、手机独立客户端、法定节假日调休或节气日程。
- 通知需要 DSH 运行、客户端连接和系统权限；后台节流、休眠与退出会影响提醒，不保证关闭后的实时通知。
- 农历事件按年重复；复杂规则应先用预览检查日期。
- 实际布局、原生全屏命中、动画小尺寸观感和平台行为，不能仅由源码测试证明。
