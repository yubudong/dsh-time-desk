# Time Desk 0.6.0

第二期 B：升级前检查、升级前快照、交给插件管理器和结果核对。**插件本身仍不执行安装。**

## 新增

- 「准备升级」在发现新版后先检查本工作台状态：运行中的专注／休息计时、打开且未保存的编辑器、时间精灵正在处理、正在保存数据。有阻挡项时逐条列出，不创建快照。
- 条件满足时保存升级前快照，记录来源版本、目标版本、时间与项目／任务／习惯／专注数量，然后打开 DSH 插件管理器。
- 安装后回到工作台，若当前版本等于目标版本，显示「已升级到 vX」，可确认并清除待升级状态。
- 最多保留 3 份升级前快照；可选择用某份快照恢复工作台数据。恢复需要确认，走已有的备份恢复校验：当前 revision 必须匹配，恢复前保留副本，并结束当前计时。
- 快照创建与恢复都有大小上限；数据过大时拒绝创建并说明原因。

## 为什么不由插件自己调用安装接口

DSH 提供 `pluginManager.updateBundle`，但它是插件管理器在用户确认后使用的；更新过程可能先卸载本插件再安装，当前插件进程中的请求会中断，且目前只有 Git 固定提交安装方式可更新（本项目未发布 npm 包）。因此这里选择保存快照后交回 DSH 插件管理器：安装动作、权限校验与结果由 DSH 自己负责，不绕过它的确认流程。

## 数据与隐私

快照保存在独立单元 `life_desk_upgrade`，仅含工作台业务状态与版本元信息；不含助手聊天、DSH Profile、模型凭据或文件路径。恢复复用已有的 `restoreBackup` 校验，不清空未知数据，不覆盖升级期间新写入而不匹配 revision 的数据。

## 边界

- 没有自动安装、静默升级或后台更新；没有跨设备同步。
- 快照不是 DSH 完整备份，也不取代用户自己的 JSON 导出。
- 安装结果只能在回到工作台后按版本核对；“仍需重启”等情况以插件管理器为准。

## 验证

新增升级前检查、快照上限、版本校验、确认与 revision 冲突、恢复后数据与计时状态等测试；真实 DSH 存储／路由验证覆盖「准备升级 → 恢复快照 → 数据仍在」。
