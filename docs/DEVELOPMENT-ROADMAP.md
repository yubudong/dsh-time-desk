## 原始问题与验收依据

## 已决定：先完善本地版

- 当前以免费分享、默认本地存储为主，不部署同步服务，不开发独立手机端。
- 同步是未来可选能力；关闭或未配置同步时，本地版继续独立使用。
- 两条未来路线可共存：维护者提供的同步服务、用户自备 NAS/WebDAV/其他云存储。
- 同一个工作台只配置一个主要同步位置；其他位置用于单向备份，切换同步位置采用明确迁移流程。
- 初期同步面向本人电脑和手机，不引入家庭多人协作。兼顾 iPhone 和安卓，电脑关机或手机在外网时仍可操作。
- PWA 或原生封装尚未定案；先验证目标存储的授权、HTTPS、跨域、外网访问与移动系统限制。
- WebDAV 是可优先验证的标准接口。百度网盘等必须分别核实正式 API、应用审核、授权和费用，不将其视作通用 WebDAV。
- 自备存储不等于免除同步开发：仍需操作去重、冲突处理、删除传播、加密、恢复及数据迁移。
- 不提前承诺公共服务器的免费额度、稳定性、手机后台实时同步或关闭应用后的可靠通知。

个人部署资产和运营考虑记在仓库之外的本机决策记录中，公开源码与发行包不携带这些信息。

## P0：课程账目、时间与历史正确性

### 1. 重复撤销需要准确关联本次扣减（已用合成数据复现）

- 位置：`src/model.js` 的 `lessonSession undo`。
- 当前以 `find(kind === "use" && sessionId)` 找到该节最早一笔扣减。
- 复现：初始10课时 → 扣1 → 撤销 → 扣2 → 撤销；预期余额10，实际9。
- 验收：不同扣减量的多轮确认/撤销都返还正确；每笔返还关联其原扣减，重复请求不重复返还。
- 同时复核系统生成的 refund 记录目前可被 lessonCharge remove 删除的问题、变更课程管理方式后撤销旧账的问题，以及小数累加精度。

### 2. 分星期时间必须贯穿上课、调课和恢复（已用合成数据复现）

- 位置：`src/lessons.js` 的 `lessonTimeFor` 与 `src/model.js` 的单次课写入。
- 当前显示按分星期计算，但写入单次记录和恢复时仍有 `lesson.time` 默认回退。
- 复现：默认19:00、周日10:00，确认周日已上课后记录变成19:00。
- 验收：显示、确认上课、请假、恢复原安排、单次调课、日历及导出都遵从同一个时间解析规则；已经记录的实际时间不被新默认值改写。

### 3. 分星期时间与提前提醒（已用合成数据复现）

- 位置：`src/lessons.js` 的 `lessonReminders`。
- 当前 `!l.time` 会跳过只设置分星期时间的课程。
- 复现：默认时间为空、周一10:00、提前15分钟；周一09:50预期一条提醒，实际零条。
- 另需验证：跨午夜提前提醒、提前一天提醒、调课通知文本仍引用课程默认时间，以及单条无效时间不能中断全部提醒。
- 验收：基于每节实际日期时间计算通知；仍明确说明 DSH 退出/休眠和系统权限的限制。

### 4. 保护排课历史，补齐“从某日开始改后续”

- 源码检查：`lesson` 动作直接替换 weekdays/time/effective 等字段，尚无课程排期版本或分段规则，不能把它称为已实现历史保护的后续调整。
- 默认未选择星期时，`lessonOccurrences` 只返回存储的单次记录；新建课程本身没有自动产生该日期的一节单次课。需补齐用户看到的“单次课程”语义。
- 验收：单次课创建后能看到并记录；调整下周起的规则不重写之前的排期、调课、出勤和账目；多次调课保留可回查记录。

## P1：年卡、界面和首页偏好

### 5. 年卡周期与历史查阅

- 复核 `upsertTerm` 缩短有效期时只约束该周期内原有记录，不能因其他周期已有上课记录而拒绝正常编辑。
- 到期课程的编辑器应正确选中已有周期，而非无意新建重叠周期。
- 上课记录支持按日期/周期查阅和补记；详情当前仅列所选日后45天内的前8项，不能替代完整历史。
- 期限课程不强制购买课时上限；累计出勤课时与课时包扣减区分文案。
- 复核未来日期不能直接确认为实际出席、请假仍收费的机构规则、到期提示开关。

### 6. 首页排序不能覆盖另一分区

- 源码检查：自定义首页的箭头和拖放都用当前分区的 `next` 替换全局 `homeModules.order`，可能丢失另一分区的自定义顺序。
- 验收：调整主区域保留侧栏顺序，反之亦然；刷新保持；取消拖动不写入；跨区拖动明确拒绝；隐藏和折叠不会相互影响。
- 检查所有承诺可折叠的模块是否有一致入口，隐藏专注后的窄屏顶部计时器表现，以及空课程模块的默认展示。

### 7. 表单草稿与类型约束

- 课程弹窗需保护未保存内容：关闭、切换窗口、刷新、网络失败、记录冲突时不能无提示丢失。
- 为页面与业务动作补明确 TypeScript 接口，降低大量 `any` 导致的入口漏传风险；此前 env.act 报错已说明只做模型测试不足。
- 数据保存成功与“工具结果返回失败”分开处理；复核 Host 返回值中 undefined 字段造成 lossless JSON 错误的路径。
- 不以 UI 文案或测试数量代替端到端操作验收。

## P1：备份、恢复与跨平台验收

- 对课程、周期、上课记录、课时流水、分星期时间、首页偏好做完整导出—恢复—重启回读测试。
- 覆盖旧备份升级、损坏文件拒绝、无效关联、重复记录、恢复失败不覆盖现有数据；快照恢复只恢复数据，不声称回滚代码。
- macOS 和 Windows 实际操作课程新增、充值、不同星期时间、请假、调课、确认上课、撤销、拖动排序、深浅色与窄屏。
- Windows 构建通过不等于原生窗口、系统通知或全屏实机验收通过。
- 升级时保留已有任务/课时/布局，不用真实个人数据做测试，不把个人截图放进仓库。

## P2：本地体验与发布一致性

- 时间精灵的课程动作 schema/说明与模型、UI 保持一致；用户明确确认后才进行账目更正和批量排课。
- npm 安装用户在 GitHub 不可用时仍能理解当前版本状态，评估公开 npm 元数据检查作为更新提示补充；由 DSH 执行安装，不做插件自更新。
